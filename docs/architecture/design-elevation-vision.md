# Design: Terrain Elevation & Height-Based Vision

## Current State
- Flat map: all terrain at same height
- Vision: purely distance-based (radius check from simcore/rules.py)
- Fog: 3-state (unexplored=0, explored=1, visible=2)
- Terrain types: PLAIN, WATER, MOUNTAIN (from simcore/map.py) — only used for walkability, not height

## Proposed
- elevation grid: 2D integer array at build-tile resolution
  - 0 = low ground
  - 1 = medium (ramp transition)
  - 2 = high ground
- Vision rule: unit at height H can see tiles at height ≤ H
  - Low→High: blocked (can't see up)
  - High→Low: visible (can see down)
  - Same height: normal distance check
- Ramp tiles: height=1, allow movement between 0 and 2
  - Units on ramps see at height 1 (see low and medium, not high)

## Data Source
- elevation grid stored in TileMap (simcore/map.py)
- Generated by mapgen (simcore/mapgen.py) from seed
  - MOUNTAIN tiles → elevation 2
  - PLAIN tiles → elevation 0
  - Transition tiles → elevation 1 (ramps)
- Or loaded from map JSON for handcrafted maps

## Vision Algorithm
```python
def can_see(unit_height, tile_height):
    return unit_height >= tile_height
```
- Replace current distance-only check with distance AND height check
- Low units lose vision of high ground (simulates "high ground advantage")

## Protocol Impact
- elevation grid included in GameStateSnapshot (V2 proto only)
- Fog update uses elevation check
- Godot renders different tile colors/tinting per elevation level
- Agent obs includes elevation info for visible tiles

## Rollback
- enable_elevation flag. Off = flat map = current behavior.
- When off, elevation grid is all-zeros, height check is always true.

## Impact Analysis
- SimCore: Fog update logic changes (add height check)
- Godot: Rendering changes (elevation-aware tile tinting)
- Agent: Gets elevation info (tactical advantage awareness)
- Tests: Must verify fog behavior with and without elevation
- Mapgen: Must generate elevation grid alongside tile types
